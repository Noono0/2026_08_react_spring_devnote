- 프론트엔드 `npm run lint`, `npm run typecheck`, `npm run test`(68개 파일·222개 테스트), `npm run build`가 통과했습니다. 이력 결과를 다시 열 때 검색 조건 초기화, 기존 방식 요청 변환 6건, CSV 큰따옴표 처리 테스트를 추가했습니다. 실제 브라우저 화면과 외부 사이트 수집은 수동으로 확인하지 않았습니다.

## 2026-09-26 — 매물 금액·층 파싱 오류 수정

- 원본 제목과 상세내용의 층수가 서로 충돌하는 행은 어느 값이 실제 해당층인지 자동으로 단정하지 않았습니다. 제공받은 기존 CSV는 덮어쓰지 않았으며, 수정된 파서를 적용하려면 다시 수집·내보내기 해야 합니다.
- `CrawlerListingParserTest`에 실제 CSV 표기를 바탕으로 회귀 테스트를 추가했습니다. JDK 21 `gradlew.bat test`: 전체 80개 중 79개 통과, 외부 사이트 테스트 1개 건너뜀, 실패 0개입니다. 외부 사이트 재수집과 새 CSV 수동 검사는 하지 않았습니다.

## 2026-09-25 — 네이버 녹화 로그인 유지 수정

- 실제 녹화 상태와 로그에서 18:23의 녹화가 `TargetClosedError`로 중단됐고, 11개 동작은 남았지만 네이버 세션 파일이 갱신되지 않은 것을 확인했습니다. 해당 오류만으로 사용자가 탭을 닫았는지 사이트가 창을 전환했는지는 구분할 수 없습니다.
- 로컬 `bootRun`의 세션 디렉터리를 로그인 도우미와 같은 `.local/crawler-sessions`로 맞췄습니다. Docker는 기존 `/application/storage/crawler-sessions` 경로를 사용합니다. 파일 저장소의 다른 경로는 변경하지 않았습니다.

- 저장 세션은 서버가 만료시킬 수 있으므로 파일 존재와 쿠키 이름만으로 현재 로그인 성공을 단정하지 않습니다. 네이버 계정의 실제 재로그인·캡차는 이번 자동 검사에 포함하지 않습니다.
- JDK 21 `gradlew.bat test`: 전체 78개 중 **77개 통과, 외부 사이트 테스트 1개 건너뜀**, 실패 0개입니다. 새 쿠키만 저장하고 기존 쿠키는 다시 저장하지 않는 회귀 테스트를 추가했습니다. 정적 검사의 JSON·XML·셸·TypeScript·Java·DAO/Mapper·Gradle 그룹은 통과했으나 현재 Python에 PyYAML이 없어 YAML 그룹은 검사하지 못했습니다.

### 삭제와 실행 구조

- 사용처가 없는 `frontend/src/app/components/SiteHeader.tsx`와 그 전용 CSS를 제거했습니다. 현재 내비게이션은 `ApplicationSidebar`가 담당합니다.
- 오래된 테스트용 `CrawlerStandaloneApplication`과 Gradle `crawlerRun`을 제거했습니다. 이 설정의 데이터소스 제외가 전체 애플리케이션 테스트에도 영향을 주어 MyBatis 구성이 실패하고 있었습니다. 현재 크롤러 설정·이력 기능은 MySQL을 사용하므로 일반 `bootRun` 진입점으로 실행합니다.
- 기능 없이 한 명령만 감싸던 `stop-docker.sh`, `verify-static.sh`는 제거했습니다. 각각 `docker compose down`, `python scripts/verify-static.py`를 직접 실행합니다.
- `start-docker.sh`는 스크립트 디렉터리로 이동한 뒤 실행하여 다른 작업 경로에서도 설정 파일을 찾도록 했습니다.
- `frontend/pnpm-workspace.yaml`의 문자열 자리표시자를 실제 boolean으로 바꿨습니다. esbuild 빌드는 허용하고 MSW worker는 문서·CI의 명시적인 `msw init` 명령으로 생성합니다.

### 성능과 로딩

- `App.tsx`의 홈 외 페이지를 `React.lazy`로 불러오고 공통 `PageOutlet`에서 로딩 상태를 처리합니다. `ApplicationLayout`과 `PortfolioLayout`의 메뉴는 로딩 중에도 유지됩니다.
- `PortfolioHomePage`의 편집기는 실제로 열 때만 렌더링하고 내려받습니다. 공개 홈 방문에 Tiptap 편집기 전체를 포함하지 않습니다.
- 같은 환경의 운영 빌드에서 메인 JS 파일은 **1,078.93 kB → 약 472 kB**, gzip은 **333.57 kB → 약 148.5 kB**로 줄었습니다. 메인 파일 기준 약 **56% 감소**이며, 나머지 페이지·편집기 코드는 필요할 때 별도로 다운로드합니다. 전체 기능 코드가 그 비율만큼 삭제된 것은 아닙니다.
- 크롤러 결과 필터의 활성 규칙 목록을 행마다 다시 만들지 않고, 키워드 중복 제거에 `Set`을 사용합니다. 백엔드는 문자열 반복 연결과 중간 boolean 목록을 제거하고 일치 결과가 정해지면 평가를 멈춥니다.

### 동작 수정

| 영역 | 이전 문제 | 수정 및 회귀 확인 |
|---|---|---|
| HTTP 옵션 | POST·PUT에서 쿼리 누락, Axios가 지정 헤더를 덮어씀 | 두 구현에서 쿼리·지정 헤더를 유지하고 MSW 계약 테스트로 검증 |
| 헤더 이름 | Fetch에서 대소문자가 다른 기본·지정 헤더가 중복될 수 있음 | `Headers.set`으로 대소문자와 관계없이 덮어씀 |
| 요청 취소 | Fetch의 timeout 0이 즉시 시간 초과로 해석됨 | 시간 제한만 끄고 호출자의 취소 신호는 유지 |
| 오류 처리 | JSON이 깨진 오류 응답에서 HTTP 상태를 잃음 | 503 등 실제 HTTP 상태를 유지하여 재시도 판단 가능 |
| 재시도 | 알 수 없는 클라이언트 오류도 재시도 | 연결 실패·시간 초과·502·503·504에 한정; 취소는 재시도하지 않음 |
| 저장 데이터 | 연락처·업무·API Workspace가 JSON 타입 단언에 의존 | 공통 `parseStoredArray`와 Zod 스키마로 항목별 검증; 유효한 항목은 보존 |
| 업무 생성 | 같은 밀리초에 생성한 업무 ID가 겹칠 수 있음 | 현재 목록과 시각을 기준으로 다음 ID를 생성하고 동시 생성 테스트 추가 |
| 크롤러 설정 | 단계 실행 후 기존 방식의 설정을 읽어도 실행 모드가 남음 | 저장 설정의 단계 유무에 따라 STEPS·LEGACY 모드 모두 갱신 |
| 크롤러 녹화 | 새 실행에 이전 녹화 단계가 남음 | 새 실행 시작 시 초기화; 녹화 종료 직후에는 가져올 수 있도록 보존 |

연락처의 호출되지 않는 RESET 분기도 제거했습니다. 학습용 업무·연락처 로그는 공통 로거를 쓰고, 입력 데이터 전체 대신 동작과 건수를 기록합니다.

### 검사 도구와 CI

- 정적 검사에서 `node_modules`, Gradle·Vite 빌드 결과와 `.local`을 탐색 전에 제외하여 불필요한 전체 순회를 줄였습니다.
- 점이 들어간 로컬 모듈명과 index 모듈을 올바르게 찾고, 폴더만 존재하는 잘못된 import는 통과시키지 않습니다.
- 루트뿐 아니라 중첩된 셸 스크립트도 검사합니다. Windows에서는 WSL 실행기 대신 Git Bash를 선택합니다.
- Java 도구는 `JAVA_HOME`을 따르며 문법 오류가 있으면 실패 코드로 끝납니다. 정상·오류 Java fixture로 종료 코드 0·1을 각각 확인했습니다.
- 구현에 특정 문자열이 들어 있는지만 검사하던 기능 검사는 제거하고 실제 동작 테스트에 맡겼습니다. Docker 서비스 검사는 YAML 구조를 읽습니다.
- PyYAML 준비 명령을 `scripts/requirements.txt`에 명시했습니다. CI의 프론트엔드 검사 job에도 Python 회귀 테스트와 저장소 정적 검사를 추가했습니다.

### 다음 작업의 시작점과 검증 한계

- 외부 크롤러 테스트는 기본값대로 건너뛰었습니다. 네이버 로그인·캡차·세션 만료 후 재인증 성공은 이번 검사 결과에 포함하지 않습니다. 실제 확인은 [크롤러 가이드](crawler.md)와 [검증 가이드](verification.md)를 따릅니다.
- Docker 이미지를 새로 빌드하거나 전체 화면을 실제 브라우저에서 수동 점검한 결과는 포함하지 않습니다. GitHub CI 설정은 수정했지만 원격 CI 실행 결과는 아직 없습니다.
- 메인 번들 크기는 이 PC에서 같은 설정으로 비교한 값입니다. 이후 의존성이나 빌드 설정이 바뀌면 다시 측정합니다.
- 저장 데이터 형식을 바꾸면 기존 데이터 호환성과 손상 항목 처리 테스트를 함께 수정합니다. `[LEGACY-FORM]`은 기존 크롤러 설정의 마이그레이션 없이 제거하지 않습니다.
- 다음 작업자는 기존 미커밋 변경과 이번 정리 내용을 현재 파일·diff와 함께 확인합니다. 실행 명령과 현재 경로를 먼저 맞춘 뒤 관련 테스트를 실행합니다.
