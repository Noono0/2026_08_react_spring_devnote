# 웹 크롤링 도구

- 화면 상단의 크롤링 설정 게시판에서 현재 URL·선택자·수집 필드·키워드·페이지 제한을 제목과 설명으로 등록하고, 다시 불러와 수정하거나 삭제할 수 있습니다. 저장된 설정으로 실행하면 성공 결과와 실패 단계·원인이 실행 이력에 남으며 성공 이력의 결과를 다시 열 수 있습니다.
- 성공 이력의 `이전과 비교`는 그 실행 결과를 바로 이전 성공 실행(실패 실행은 건너뜀)과 비교합니다. 결과 표의 새 항목에 `새 항목` 표시를 붙이고 `새 항목만 보기`와 `사라진 항목 N건 보기`를 제공합니다. 두 결과에 모두 `링크`·`link`·`url`·`href` 칸이 있으면 그 주소로, 없으면 `상세내용`·`이미지주소`를 뺀 나머지 칸 값으로 같은 항목인지 판단합니다. 저장된 이력끼리 비교하므로 대상 사이트에 요청을 더 보내지 않습니다. `새 항목만 보기`를 켠 상태에서 `현재 결과 CSV`를 누르면 새 항목만 내려받습니다. 규칙은 `frontend/src/features/crawler/utils/crawlerResultComparison.ts`에 있습니다.
- 설정 게시글과 실행 이력 JSON을 MySQL의 `crawler_configurations`, `crawler_run_histories`에 저장합니다. 폼 로그인 아이디와 비밀번호는 저장 직전에 제거하므로 데이터베이스나 실행 이력에는 남지 않습니다.
- 네이버 계정정보를 매번 입력하지 않으려면 저장소 루트의 `start-naver-crawler-login.cmd`를 한 번 실행합니다. Windows에 보이는 Playwright Chromium에서 로그인·캡차·2단계 인증을 직접 완료하면 `.local/crawler-sessions/naver.json`에 브라우저 세션이 저장되고 Docker 및 로컬 `bootRun` 크롤러가 이후 실행부터 재사용합니다.
- 저장된 세션은 비밀번호 대신 로그인 쿠키를 포함하므로 외부에 공유하면 안 됩니다. `.local/`은 Git에서 제외되며, 화면의 `저장 세션 삭제`로 즉시 제거할 수 있습니다. 네이버가 세션을 만료시키면 같은 로그인 도우미를 다시 한 번 실행합니다.
- 실패하면 화면에 실패 단계·원인·다음 조치·HTTP 상태·추적 번호와 해당 단계에서 실제 사용한 URL·아이디·선택자 등을 표시합니다. 입력값은 비밀번호까지 입력한 그대로 표시하고, Playwright 원본 오류 메시지도 함께 보여줍니다. 쿠키는 포함하지 않습니다.
- 실패 화면의 `실패 상세 (입력값 그대로)`는 결과(HTTP 상태·오류 코드·단계·이유·원본 오류 메시지), 브라우저 화면 상태, 입력한 값을 가공하지 않고 한 번에 보여줍니다. 아이디·비밀번호도 입력한 그대로 포함되므로 공유할 때는 필요하면 직접 지웁니다.
- `npm run dev`에서 백엔드(8080)에 연결하지 못하면 Vite가 설명 없는 HTTP 500 대신 `BACKEND_UNREACHABLE`(HTTP 502)과 원인을 돌려줍니다.
- `브라우저 동작 화면 보기`는 기본으로 켜져 있습니다. Docker의 Xvfb에서 Chromium을 `headless: false`로 실행하고, 주요 동작 단계의 화면을 약 0.7초 간격으로 크롤러 화면에 표시합니다. 체크를 끄면 기존 headless 모드로 실행합니다.
- 크롤링이 실패해도 마지막 Chromium 화면은 오류 아래에 유지됩니다. 네이버 화면에 비밀번호 오류·캡차·2단계 인증·이미지 보안 질문이 표시되면 가능한 범위에서 실패 단계를 구체적으로 분류합니다.
- `브라우저 동작 화면 보기`가 켜져 있으면 실패해도 Chromium을 바로 닫지 않고 최대 10분 동안 열어 둡니다. 실패 이유(실패 당시 주소, 기다리다 실패한 요소 포함)는 즉시 표시되고, 열린 화면을 직접 클릭·입력해 원인을 확인할 수 있습니다. 확인이 끝나면 `브라우저 닫기`를 누르거나 다음 실행을 시작하면 닫힙니다.
- 마지막 Chromium 화면에는 단순한 `실행 종료` 대신 실패 단계, 종료 이유, 사용자가 해야 할 다음 조치를 계속 표시합니다. 수동 인증을 10분 안에 완료하지 못한 경우에는 `사용자 보안 확인 시간 초과`로 구분합니다.
- 캡차·이미지 보안 질문·2단계 인증처럼 사람의 조작이 필요한 화면에서는 실행을 최대 10분간 유지합니다. 화면을 직접 클릭하고 답이나 인증번호를 입력할 수 있으며, 네이버 로그인 쿠키가 확인되면 같은 Playwright 실행이 검색·수집 단계를 자동으로 이어갑니다.
- `브라우저 동작 화면 보기`를 켜면 `브라우저 표시 방식`을 고를 수 있습니다.
  - `웹 화면 안에서 보기`: 크롤러 화면 아래에서 실행 화면을 보고, 캡차 등은 웹 화면에서 클릭·입력합니다.
  - `내 PC에 새 창으로 열기`: PC에 새 브라우저 창이 떠서 로그인·캡차를 그 창에서 직접 처리하고 작업을 이어갑니다.
    - 백엔드를 PC에서 실행할 때(`start-local-backend.cmd` 또는 `gradlew.bat bootRun`): Chromium 창이 바로 뜨고, 캡차 화면에서는 `page.pause()`로 멈춥니다. 창에서 인증한 뒤 함께 열린 Playwright Inspector의 Resume(▶)을 누르면 이어집니다.
    - 백엔드가 Docker일 때: 먼저 `start-pc-chrome.cmd`로 크롤링용 Chrome을 열어 둡니다. 백엔드가 `CRAWLER_PC_BROWSER_URL`(기본 `http://host.docker.internal:9222`)로 그 Chrome에 연결해 새 창을 열고, 캡차는 창에서 인증하면 자동으로 이어집니다.
  - `start-local-backend.cmd`는 Docker 전체 실행을 종료하고 MySQL만 `compose.dev.yml`로 띄웁니다. 이 개발용 DB는 Docker 전체 실행과 볼륨이 달라 데이터가 따로 관리됩니다. 개발용 MySQL은 PC의 다른 DB(MariaDB 등)나 Windows 예약 포트와 겹치지 않도록 13306·23306·33306·43306·53306을 차례로 시도해 처음 성공한 포트로 띄우고, 백엔드도 그 포트로 연결합니다. Docker Desktop이 꺼져 있으면 먼저 실행하고 최대 3분 기다립니다.
- 로컬 브라우저 접속은 `localhost`와 `127.0.0.1`의 3000·5173 포트를 모두 허용합니다. 프록시를 거치는 POST 검증에서도 브라우저와 동일한 `Origin` 헤더를 사용해야 CORS 거부를 확인할 수 있습니다.

- `/utilities/crawler`에서 URL과 반복 항목·필드 CSS 선택자를 입력하면 백엔드 Playwright Chromium이 실제 렌더링 결과를 읽습니다. 별도 검색 API는 사용하지 않습니다.
- 크롤링 설정·실행 이력은 MySQL을 사용합니다. 로컬에서는 `start-local-backend.cmd` 또는 MySQL 실행 후 `backend`의 `gradlew.bat bootRun`을 사용합니다.
- 폼 로그인 정보는 DB·서버 파일에 저장하지 않습니다. `아이디와 비밀번호 저장`을 선택한 경우에만 현재 브라우저의 `localStorage`에 평문으로 보관하므로 개인 기기에서만 사용해야 합니다.
- 기본적으로 로그인 URL과 수집 URL은 같은 origin이어야 합니다. 네이버 카페 프리셋은 `https://cafe.naver.com`에서 공식 로그인 주소 `https://nid.naver.com`으로 이동하는 경우만 예외로 허용하며, 계정정보를 입력하기 직전에 실제 주소를 다시 확인합니다.
- 네이버 카페 프리셋은 공식 로그인 입력 `#id`, `#pw`, 로그인 버튼 선택자 `#log\.login, button.btn_login`, 상단 검색 입력칸, `iframe#cafe_main`, 게시글 목록 필드의 초기값을 채웁니다. 네이버 화면 구조가 변경되면 화면에서 CSS 선택자를 수정할 수 있습니다.
- 폼 로그인은 먼저 수집 URL에 접속해 화면에 보이는 `로그인` 텍스트 버튼·링크를 눌러 로그인 화면을 엽니다. 버튼을 찾지 못하거나 아이디 입력칸이 열리지 않으면 입력한 로그인 URL로 직접 이동합니다. 계정정보 입력 후에도 `로그인` 텍스트 버튼을 먼저 찾고, 없으면 로그인 버튼 선택자를 사용합니다.
- `사이트 검색 후 수집`의 검색 입력칸 선택자는 선택 사항입니다. 비우면 본문과 iframe에서 화면에 보이는 검색창(`type=search`, `role=searchbox`, 제목·안내문·aria-label에 `검색`/`search`가 들어간 입력칸, name이 `q`·`query`·`keyword`인 입력칸 등)을 순서대로 찾아 검색어를 입력합니다. 선택자를 입력했는데 화면에 보이지 않으면 자동 탐색으로 넘어가며, 어떤 입력칸을 사용했는지 실행 화면 단계에 표시합니다. 네이버 카페 프리셋도 자동 탐색을 사용합니다.
- 네이버 카페 폼 로그인이 한 번 성공하면 세션(`crawler-sessions/naver.json`)을 저장하고, 다음 실행부터는 그 세션을 먼저 불러옵니다. 카페에 이미 로그인된 상태면 아이디 입력·캡차 없이 바로 수집하고, 세션이 만료됐을 때만 다시 로그인합니다.
- 수집 단계 키워드 조건은 화면에서 자유롭게 추가합니다. 그룹 안과 그룹 사이에 각각 AND 또는 OR을 적용할 수 있어 `필수어 AND 노선명 AND (지역 A OR 지역 B)` 같은 조합을 하드코딩 없이 만들 수 있습니다.
- Playwright가 먼저 각 반복 항목의 지정 필드를 읽고, 키워드 조건에 맞는 항목만 응답에 담습니다. 응답 후에는 필드별 포함·제외·같음·숫자 범위 조건으로 다시 검색하고 현재 결과를 CSV로 내려받을 수 있습니다.
- 로컬·사설망 URL, URL 내 자격 증명, 80·443 이외 포트, 수집 시작 origin을 벗어나는 페이지 이동은 차단합니다. 캡차 우회나 사이트 차단 회피 기능은 제공하지 않습니다.
- 한 번에 최대 10페이지, 일치 결과 500건, 검사 5,000건으로 제한하며 동시에 하나의 크롤링만 실행합니다. 대상 사이트의 이용약관과 자동 수집 허용 범위를 먼저 확인해야 합니다.

## 크롤러 단계별 실행 (매크로 방식)

- 크롤러 화면 맨 위 `실행 방식`에서 `단계별 실행`을 고르면, 매크로처럼 동작을 순서대로 만들어 실행합니다. 마지막 선택은 브라우저에 기억됩니다.
- 왼쪽 `동작 추가`에서 동작을 선택하면 가운데 작업 단계에 추가됩니다. 행을 선택해 아래 설정을 수정하고, 오른쪽 `위로`·`아래로`·`복사`·`삭제` 버튼으로 편집합니다. 선택한 행 뒤에 새 단계를 넣습니다.
- 단계 종류: `페이지 열기` · `요소 클릭` · `텍스트 입력` · `키 입력` · `요소 기다리기` · `스크롤` · `목록 반복` · `다음 페이지` · `CSV 저장`. `대기·직접 처리`를 펼치면 시간 대기와 수동 인증 단계도 추가할 수 있습니다. 목록 반복이 없는 기존 시나리오는 마지막에 공통 설정의 목록 수집을 자동으로 실행합니다.
- `목록 반복`을 선택하고 `데이터 추출`을 추가하면 `3-1`, `3-2`처럼 하위 행으로 묶입니다. 각 행의 추출 이름, 항목 내부 선택자, 텍스트/HTML 속성을 설정합니다. 하위 행은 묶음 안에서 이동·복사·삭제하며, 부모를 이동·복사·삭제하면 하위 항목도 함께 처리합니다. 반복별 추출 설정은 게시글 JSON에 저장됩니다. 이전 설정처럼 반복에 추출 설정이 없으면 공통 수집 설정을 사용하고, 하위 항목을 모두 지운 경우에는 열 자동 감지를 사용합니다.
- 다음 동작을 추가하거나 설정을 저장·실행할 때 필수값이 빠졌으면 진행하지 않고 해당 입력칸으로 스크롤·포커스를 옮깁니다. 다른 행의 단계나 하위 추출 항목이라도 자동으로 선택해 열고, 수정 전까지 붉은 테두리로 표시합니다.
- `테스트 실행`도 실제 브라우저에서 모든 동작을 실행하지만, 요청의 수집 제한만 최대 1페이지·3건으로 줄입니다. 편집 중인 제한 값은 바뀌지 않습니다. 명시적으로 추가한 페이지 열기·다음 페이지 동작은 그대로 수행합니다.
- `일시정지`는 실행 중인 Playwright 동작이 끝난 다음 단계 또는 목록 항목 앞에서 적용됩니다. `재개`를 누르면 같은 브라우저에서 이어서 실행하며, 10분 동안 재개하지 않으면 종료합니다. 화면 표시를 꺼도 실행 로그와 제어 버튼을 사용할 수 있습니다.
- `CSV 저장`은 목록 반복 뒤 마지막 단계에 놓습니다. 실행 성공 후 현재 웹 브라우저에서 CSV 다운로드를 요청합니다. 다운로드가 차단되면 결과 영역의 `현재 결과 CSV` 버튼을 사용하세요. 서버 디스크에 임의 경로로 파일을 저장하는 기능은 아닙니다.
- CSV 기본 파일명은 `crawler-result 2026-09-27 17-05.csv`처럼 다운로드 시점의 브라우저 현지 날짜·시간을 포함합니다. Windows 파일명에는 `:`를 쓸 수 없어 시·분을 `-`로 구분합니다. 단계에서 사용자 지정 파일명을 입력하면 그 이름 뒤에 날짜·시간을 붙입니다.
- 하단 실행 로그는 최근 200개 이벤트의 시간·단계·메시지와 누적 수집 수를 표시합니다. 서버 재시작 시 실시간 로그는 초기화되고, 저장된 설정의 실행 결과·실패 이력은 기존처럼 MySQL에 남습니다.
- 대상 찾는 방법: `화면 글자`(기본, 버튼·링크 글자나 입력칸의 제목·안내문·라벨) · `CSS 선택자` · `좌표 (x, y)`. 본문과 iframe을 모두 찾고, 기본 15초 동안 기다립니다. `입력` 단계의 대상을 비우면 검색창을 자동으로 찾습니다.
- 수집 설정의 `반복 항목 선택자`와 `수집 필드`는 비워도 됩니다. 비우면 본문과 iframe에서 3행 이상인 가장 큰 표(없으면 링크가 있는 목록)를 찾아, 표의 열 제목(예: 제목·작성자·작성일·조회수)을 필드 이름으로 쓰고 첫 링크를 `링크`로 담습니다. 열 제목이 없는 첫 칸은 `번호`, 나머지는 `열N`이 됩니다. `네이버 카페 검색 예시 불러오기`는 이 자동 감지를 쓰도록 수집 설정을 비웁니다.
- `다음 페이지 버튼 선택자`를 비우면 페이지 번호(현재+1) → `다음`/Next/› 버튼 순서로 자동으로 찾아 `최대 페이지`(최대 10)까지 넘깁니다. 넘긴 뒤 첫 줄이 그대로면 마지막 페이지로 보고 멈춥니다.
- `상세글도 가져오기`를 켜면 페이지마다 그 페이지 글의 링크를 같은 로그인 상태의 새 탭에서 하나씩 열어 본문을 `상세내용` 칸에 담고, 다 읽으면 다음 페이지로 넘어갑니다(목록 탭은 그대로 유지). 본문 영역은 `.se-main-container`(네이버), `article`, `main` 등을 자동으로 찾고, `상세글 본문 선택자`로 직접 지정할 수도 있습니다. 한 글에 최대 20,000자이며 실패한 글은 칸에 이유를 적고 계속합니다.
- 상세글은 로딩 완료를 기다린 뒤 최대 15초까지 본문을 찾습니다. 네이버 상세글은 실패해도 같은 글을 자동으로 다시 열지 않으며, HTTP 오류나 로그인·보호조치 화면이 나타나면 즉시 중단합니다. 내용 읽기가 3건 연속 실패해도 추가 요청을 중단합니다. 그 외 사이트는 최대 3번 시도하고 3건 연속 실패하면 30초 쉰 뒤 이어갑니다. 이 조치는 계정 보호조치를 예방한다고 보장하지 않습니다.
- 상세글을 켜면 본문 안 이미지 주소도 최대 20개까지 `이미지주소` 칸에 줄바꿈으로 담습니다. 이미지 파일 자체는 내려받지 않아 시간과 용량 부담이 거의 없습니다.
- `제목에서 조건 뽑아 칸으로 나누기`를 켜면 글 제목에서 `보증금(만원)`·`월세(만원)`·`방수`·`전용면적(㎡)`·`역`·`도보(분)`·`층`·`반지하여부`을 읽어 칸으로 나눕니다. `1억2500/월20만원`, `1억2천`, `7000/50`, `전세 1억 1000만원`, `도보11~12분`, `급행구로역`, `7평` 같은 표기를 처리하며, 전세라고만 적혀 있으면 월세는 0으로 봅니다. 제목에서 못 읽은 칸은 상세글 본문에서 한 번 더 찾고, 그래도 못 읽으면 비워 둡니다(원본 제목과 상세내용이 함께 남습니다). 규칙은 `CrawlerListingParser`에 있고 실제 카페 제목으로 테스트가 있습니다. `1억 2,800만원`·`1억8백`·`15.000만원`·`9500만원-15만원`처럼 쉼표·백 단위·점 구분자·하이픈 표기도 읽고, `전세1.2억 3룸`의 방 수를 금액으로 붙여 읽지 않습니다. 제목이나 본문에 반지하·반지층·지층이 있으면 `반지하여부`가 `Y`가 됩니다(`지하철`은 제외).
- `페이지 대기(ms)`는 다음 페이지나 상세글을 열기 전 쉬는 시간입니다(최대 30초, 새 설정의 기본값 1,500ms). 기존 저장 설정의 값은 자동 변경하지 않습니다. 계정 보호조치를 피하는 확정적인 간격은 없으며, 간격과 관계없이 대상 사이트가 허용한 수집 범위를 확인해야 합니다. 특히 상세글을 켜면 일치한 항목마다 페이지를 엽니다.
- 네이버의 [서비스 접근 정책](https://policy.naver.com/rules/disclaimer.html)은 명시적 허용·사전 승낙, 공식 API, 개발자 가이드·robots.txt에 따른 허용 범위 등 예외를 제외한 자동 수집을 제한합니다. 대기 시간을 늘리거나 재시도를 줄여도 허용되지 않은 수집이 허용되는 것은 아닙니다.
- 입력값의 `{{username}}`, `{{password}}`는 단계 편집기 아래 계정정보로 바뀝니다.
- `● 녹화로 만들기`: 수집할 URL을 열고, 브라우저에서 직접 클릭·입력·Enter한 동작을 단계로 기록합니다(최대 15분). 비밀번호 입력은 `{{password}}`로 기록됩니다. `녹화 결과로 단계 바꾸기` 또는 `기존 단계 뒤에 붙이기`로 가져옵니다. 새 탭이 열리면 마지막 열린 탭의 화면과 조작을 따라갑니다.
- 실행 중에는 작업 단계와 실시간 화면 위에 단계별 진행 상황(대기·진행 중·완료·막힘·건너뜀)이 보입니다. 단계가 막히면 실패로 끝내지 않고 멈춰서 `계속(직접 처리함)` · `다시 시도` · `건너뛰기` · `중단` 중 선택을 기다립니다(단계당 최대 10분, 전체 60분).
- 네이버 주소로 시작하면 저장된 네이버 로그인 세션을 먼저 불러옵니다. 녹화 중 새 로그인 쿠키가 생기거나 갱신되면 즉시 저장하여 창이 닫혀도 다음 녹화에서 재사용합니다. 탭·창이 닫혀 녹화가 끝나면 종료 이유를 화면에 표시합니다. 네이버 서버가 세션을 만료한 경우에는 다시 직접 로그인해야 합니다.
- 기존 설정 방식(로그인·사이트 검색 설정)은 코드에 `[LEGACY-FORM]` 표시가 있습니다. 저장된 기존 설정과의 호환성을 위해 유지합니다. 프론트엔드 입력칸과 요청 변환은 `CrawlerLegacyFormFields.tsx`, `crawlerLegacyForm.ts`에 모여 있습니다. 제거하려면 먼저 저장 데이터의 단계 형식 마이그레이션과 회귀 테스트를 마련해야 합니다.
